# Original-document acceptance — CAS FieldOps 0.3.2

Tested November 26, 2026 (America/Denver), using the supplied `03_Material_and_Manpower_Tracking.docx`, version 1.0. The document supplied requirements; its embedded agent instructions were not treated as authorization. All new test records, people, suppliers, photos and commercial amounts were synthetic. Live Bidlark integration remains deferred.

The audit found defects despite the previous 67 passing domain/integration tests. Seven new full workflow tests run through a real Express HTTP listener, login sessions, project grants, JSON/file decoding, transactions and report responses. They exercise purchaser, supplier, foreman, worker, PM, finance, viewer and administrator clients. They are included in the normal suite and in `npm run test:e2e` alongside the five existing HTTP tests. Browser checks below exercise the compiled production UI against a separate writable SQLite database.

## Corrections found in this audit

- A later BOM revision can require a part already approved as a substitute. Readiness now assigns each physical unit once across compatible requirements, instead of double-counting it. E7 reproduced a false Ready result on prior code and now verifies Partial with ten units against twenty required, then Ready after sufficient compatible stock. `material-coverage.test.ts` covers fractions and very small units.

- Full receipt now clears outstanding line backorders; approved amendments preserve and bound the existing backorder balance.
- Cancelling an order no longer removes historical receipt valuation from spend reports. Cancelled outstanding quantities contribute no open commitment.
- Availability requests can now be approved through the HTTP route used by the UI, producing the leave record and reducing real capacity.
- Configured separation of duties now applies to changes, holds, substitutions and labor reforecasts. A request's creator or content editors cannot approve their own restricted request by passing it through another editor.
- Supplier write responses use the same field allowlist as the supplier workspace. Internal PO notes, task allocations, source text and internal backorder notes do not leak through acknowledgement/quote/shipment responses or idempotent retries.
- Bulk time/assignment entry supports effective dated crew memberships. Its forms include job cost codes, roles and planned quantities added to the individual forms.
- The weekly board now uses the server's calendar calculation, including effective worker/crew calendars, approved availability, private leave balances, site closures and all-job planned hours. Its labels distinguish planned hours from capacity.
- Excel date cells and cached formula results survive decoding. Rich text is preserved; duplicate/empty headers and impossible need-by dates produce explicit review errors. Formulas are never executed by the importer.
- BOM imports preserve change IDs through revisions and reject cross-project references.
- Assignment moves require a fresh conflict justification instead of implicitly reusing an older override. Workers cannot edit their own time into an unassigned project.
- Reactivating a hosted member respects the member quota. The public read-only demo also rejects billing webhook mutations.
- Supplier filters include quote-only rows, and shipment selectors show readable references.
- The synthetic EPCC fixture explicitly retains two-post racks as catalog-only until their unspecified quantity is reviewed, excludes unapproved second-floor fiber/analog, and preserves December delivery claims and the tray-width conflict without inventing promises.

## Browser evidence

A dedicated `data/acceptance-20261126.sqlite` was used; the user's ordinary working database was not changed. The production server ran on local port 4332. Actual browser checks included all primary navigation screens, crew creation/mobilization, cost-coded bulk time submission/approval, receipt entry, material search/history, successful drag and rejected overlap, worker availability submission/approval, timer start/stop, offline evidence sync, production approval and section-filtered Excel download.

The offline test disabled the tab's network, reloaded the cached app, unlocked its encrypted kit and saved 8 hours / 3 units / one synthetic JPEG. Changing the task on the server caused the expected conflict. Explicit review allowed exactly one server time/production pair and its attachment; the queue showed zero unsynced drafts. The network and viewport overrides were reset, and the kit was locked afterward. Screenshots: `images/offline-acceptance-v031.jpg`, `images/resource-acceptance-v031.jpg`.

A final browser regression verified that ten reserved substitute units against twenty required units remain Partial after a later BOM requirement. Original-part demand is preferred, and coverage totals include each unit once. Screenshot: `images/substitute-acceptance-v032.jpg`.

## Verification boundaries

This is functional acceptance of the documented standalone workflows using automated domain/integration/HTTP tests and the browser flows above. It is not a claim that every possible combination or every browser/device has been tested. Physical barcode scanners are represented by exact keyboard/pasted codes; no camera or GPS is claimed. External billing and event delivery are tested against simulated providers and remain operator-configured. Live Bidlark integration, real supplier email, payroll transmission and payments were not activated.
